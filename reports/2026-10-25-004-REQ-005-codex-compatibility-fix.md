# REQ-005 Codex接続の互換性不具合の修正

UIで返答が空のまま失敗した原因は、アプリがCodexへ送る `turn/start` の `sandboxPolicy.readOnly.access` が実CLIで廃止されていたことだった。認証は正常で、生成開始前の要求検証で拒否されていた。通信形式を修正し、実AIの基本応答と、HTTP API経由の応答・構造化Markdown下書き生成を確認した。起動中のローカルbackendにも反映済み。

対象は [REQ-005 revision 2](../requests/2026-10-25-001-REQ-005-discussion-chatbot.md) AC-03/04/06の不具合修正。研究内容や研究コードは変更していない。ユーザーの失敗報告を受けた保守対応として実施した。

## 原因と修正

認証済みの実CLI0.163.0を、アプリと同じ専用CODEX_HOMEで調査した。`account/read`は正常で、選ばれたモデルは `gpt-6.1-sol`。`turn/start` は次の固定の検証エラーを返した。認証情報・会話本文は診断出力に含めていない。

```text
-32600: Invalid request: readOnly.access is no longer supported;
use permissionProfile for restricted reads
```

CLIの `generate-json-schema` が生成するReadOnlySandboxPolicyにも `access` はなかった。一方、参照した [OpenAI Docs: Codex App Server](https://learn.chatgpt.com/docs/app-server) の読取制限の説明には旧項目が記載されていたため、実行するCLIの生成schemaと実通信を根拠に、送信形式を `sandboxPolicy: {type: 'readOnly'}` に合わせた。

threadの読み取り専用設定、ツールの無効化、`approvalPolicy: never`、承認・ツール要求の拒否は維持した。書込やネットワーク許可を増やしていない。ただし旧 `readableRoots` によるOS側の読取ルート制限は指定しない。選択資料をbackendが渡し、AIのツール利用を無効化する構成であり、OSが選択資料以外の読取を全面的に制限する、と説明してはならない。

元のエラー処理は認証以外の失敗を一律のメッセージに変換しており、どの通信で失敗したか判別できなかった。検証エラーでは内部のRPCメソッド名と数値コードを表示し、生のエラー本文はUIへ返さないようにした。

関連して、再試行が失敗した後に元のボタンを押しても、失敗済みの再試行を返して終わる問題を修正した。同じユーザー入力の `messageId` ごとに、待機中・実行中・完了済みのattemptを検索する。再試行も失敗した場合は新しく実行でき、親子の異なる失敗表示から押しても二重生成しない。

変更ファイルはbackendの `src/ai.ts`、`src/chat.ts` と対応する2つの試験ファイル。frontendの変更は不要だった。

実AIの検証には専用の一時workspaceとDBを使い、研究資料やユーザーの実会話は送っていない。接続確認の短い入力だけを与え、下書きは生成まででreports/へ保存していない。検証後に一時workspaceとDBを削除した。診断用のスレッドはアプリ専用Codex状態に残り得るが、Git対象外である。

初期実装時の模擬Codexは旧項目を拒否しなかったため、この互換性問題を検出できなかった。今回は模擬プロセスにも実CLIと同じ拒否条件を入れ、送信policyが `{type:'readOnly'}` と完全一致することを検査した。

Dockerイメージの実ビルド・起動、実AIでの複数担当議論・中断・再接続は引き続き未確認。基本応答と下書き生成が成功したことを、これらすべての確認完了には読み替えない。
