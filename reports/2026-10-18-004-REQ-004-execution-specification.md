# 回答者別の統合と、不一致の根拠を尋ねるAI予行の実行仕様

## 1. 目的と実行範囲

本仕様では、本人の判断知識を反映した危険度順位が本人順位と異なるときに、どの回答と場面条件が算出差に関わったかを追跡し、その説明への参考度・最終受容を取得する。説明前の順位一致と説明後の回答を分けて報告することで、不一致の解釈に必要な情報を増やす。

実行根拠は[REQ-004 revision2](../requests/2026-10-18-001-REQ-004-additional-questionaire.md)と研究責任者の「OK。自律的な作業に着手せよ」である。下位リスク変換、既存のAHP・1B原回答、旧算出結果を維持し、ファジィ統合の回答者別化と評価接続を行う。所要時間制約はいったん外す。以下は実装・予行の仕様である。実装・検証・AI予行は完了し、実行結果は[総括006](2026-10-18-006-REQ-004-pilot-assessment.md)、独立検証は[査読005](2026-10-18-005-REQ-004-execution-review.md)に記録した。

### 2.2 四条件の順序と高低

保存上の正規順序は全群とも`HH, HL, LH, LL`。第1文字が第1入力、第2文字が第2入力を表す。値は危険度1〜5の整数で、計算時には`(回答値−1)/4`へ変換する。下位入力・後件はいずれも無次元の有限値で、計算域は0〜1である。

| 群／出力ID | 第1・第2入力 | 正規回答と既存実装の対応 |
| --- | --- | --- |
| `internal`／`INTERNAL_RISK` | 属性・年齢によるリスク、行動リスク | 1B No.1〜4を順に再利用 |
| `watching`／`EXTERNAL_DYNAMIC_RISK` | スタッフ距離リスク、視野外であることのリスク | 追加4問。現aggregatorのルール順はHH・LH・HL・LLなので正規配列を`[0,2,1,3]`へ並べ替える |
| `external`／`EXTERNAL_RISK` | 周囲物体リスク、見守り状況のリスク | 原設問No.5〜8はHL・HH・LL・LH。正規順はNo.6・5・8・7 |
| `total`／`TOTAL_RISK` | 内的リスク、外的リスク | 1B No.9〜12を順に再利用 |

上記の外的リスクの順序は、v13 Table 3の「見守るスタッフあり」を見守り不足の低リスク、「なし」を高リスクとして対応させたもの。[現ローダー](../master_thesis_modules/risk_core/engine/profile_config.py)と[旧実装](../master_thesis_modules/scripts/fuzzy/fuzzy_reasoning_v5.py)の0始まり行`[5,4,7,6]`とも整合する。既存TFNの外的部分を正規配列のまま書き込むと二重変換になるため、書出し・読込を往復検証する。

見守りの追加質問は、HH＝遠い・視野外、HL＝遠い・視野内、LH＝近い・視野外、LL＝近い・視野内、とする。「患者がスタッフの視野内にいるか」という設問を用い、研究実装では移動方向を視線の代理とする既存の仮定を維持する。視線を実測したとは記載しない。複数スタッフからの下位リスクの求め方も現行のままとする。

1Aの25番目は原値と位置を保持する。Qdとの対応、左右の比較項目と比の向きが原資料から確定しない限り、`mapping_status: unresolved`としてペルソナの意味付けや後件の生成へ用いない。一対比較1値から四後件を一意に推定しない。

### 2.4 算出根拠の追跡

順位が異なる患者対について、実際の場面条件→下位リスク→本人の適用回答→上位リスク→最終スコア差を保存する。各ファジィ段階は四条件の発火重み`w_j`と本人後件`c_j`を保存し、出力を`Σw_j c_j / Σw_j`から再現できるようにする。現行の二入力high/lowでは重みの和は1となる。二患者の局所ノード差は`Σc_j(w_Aj−w_Bj)`で分解できるが、その項を最終スコアへの寄与と取り違えない。

物体条件と見守り条件の影響の切分けには、患者の属性・行動を固定したまま物体値、距離値、視野外リスク値を交換する診断を保存する。単一の置換だけでは交換順による相互作用を捉えきれないため、必要な組合せを併記する。診断値は仮想的な入力の計算であり、実際の場面の算出結果と別欄に置く。

全スコア差の診断として、5群`(属性, 行動, 物体, 距離, 視野外)`を患者BからAへ交換する32条件の厳密Shapley分解を用いる。各群の値は現行下位変換後の値とし、本人の四群ルールを固定する。基準は患者Bの実値であり、ゼロ入力ではない。寄与の和が`T_A−T_B`となることを検証する。PMが今回の算出根拠の診断として採用した。研究の主要指標や、人の判断の原因を確定する手法としては扱わない。

5群の集合をN、Sに属する群だけ患者Aの値へ置換したスコアをv(S)とすると、群gの寄与は次式となる。計算量は患者対あたり32回の階層計算である。

\[
\phi_g=\sum_{S\subseteq N\setminus\{g\}}
\frac{|S|!(4-|S|)!}{5!}\{v(S\cup\{g\})-v(S)\},
\qquad \sum_g\phi_g=T_A-T_B.
\]

場面差と本人ルールが組み合わさった結果を示し、「回答者が矛盾した」「物体だけが原因」とは自動判定しない。最大の診断寄与だけを抜き出して断定する説明も避ける。

## 3. 方法：AI予行と追加質問

### 3.1 実行順序

1. 元回答と旧結果のハッシュを取得し、新規保存先を用意する。S01・S02では保存された回答・理由から新しい人物指示を作り、旧指示の復元とは称さない。
2. 本人役へ元回答と場面を提示し、不足の見守り4問、説明前の順位・理由を取得して確定する。この段階で算出結果・計算根拠を見せない。
3. 回答検証後、回答者別の四群で算出する。動作統合の`weighted_sum / weighted_max`は既存比較条件を維持し、集計を混ぜない。
4. 不一致の場面だけ根拠を提示し、参考度・受容・自由理由を取得する。一致場面は追加質問を省き、未質問として保存する。
5. S01・S02について、順序変換、全四群適用、説明の根拠、三軸の分離を確認してから14名由来の匿名AIスタッフへ進む。実回答を上書きせず、不足分だけ追加する。

複数の算出条件があるときは、条件別に同じ説明前の人物状態を基に分岐し、別条件の説明・回答を後の分岐へ混ぜない。採用条件を結果に合わせて選ばない。

### 3.2 スタッフに提示する説明と設問

説明は「あなたの設問回答→この場面の計算判断→本人順位との差」の順にする。実際に適用された回答と場面条件を用い、一般的な研究者向け用語や仮想置換値を本文へ並べない。

> アンケートでは「［条件］」の危険性を「［回答］」と答えていました。この場面では［実際の物体・見守り条件］であるため、システムはその回答を使い、［患者A］を［患者B］より優先する順を算出しました。最初の回答では［元の順序］だったので、この2人の順が異なりました。

参照した回答が複数なら列挙し、単一設問の帰結のように書かない。患者対の説明と4患者全体の順位を区別して示す。

| 設問 | 保存値と扱い |
| --- | --- |
| 「この説明は、見守りの順を考える参考になりますか」 | 1全く参考にならない／2あまり参考にならない／3どちらともいえない／4やや参考になる／5とても参考になる。判断不能は別値 |
| 「説明を読んだうえで、システムが示した4人全体の順を受け入れられますか」 | `accept / partial / reject / uncertain`。患者対だけの受容を全体の受容へ補完しない |
| 「最初に順位を決めたときに重視したことと、アンケートで重視したことについて、同じ点や違う点があれば教えてください。算出された順への考えも、理由とともに教えてください」 | 自由回答。違いがある、現場では見落とす、受容する等の想定理由を先に提示しない |

参考度の5件法は[報告003](2026-10-18-003-REQ-004-implementation-readiness.md)の文献に基づく適用であり、この三軸一式の妥当化済み尺度とはしない。最終順位を任意取得する場合も、受容の自己申告とは別欄に置く。

## 4. 結果の記録と報告方法

一致は説明前の4患者の順位全体を比較し、同順位を維持する。既存のcompetition rank規則と浮動小数の扱いを維持する。患者対単位の不一致は根拠確認の単位として併記する。順位一致・参考度・受容の三軸は記述的に別集計し、既存主要指標やその採否を無断で変更しない。「一致または受容」という合算指標は本仕様では導入しない。

報告本文は目的→方法→結果→考察の順にする。各事例で、場面と人物設定、実際のアンケート回答、算出した危険度と順位、本人の初回順位、説明文、説明後回答を一続きで示す。参考度と受容の集計では、不一致として質問した件数を分母に明記する。

考察では、計算上どの差が影響したか、本人役の理由と何が同じ／異なるか、説明が参考になっても受容されない例は何を示すかを論じる。人物設定から予想した回答と実際に得た回答を分け、AIの受容を実スタッフの有効性の証拠として扱わない。
