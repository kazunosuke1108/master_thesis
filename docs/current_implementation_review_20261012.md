### 2.2 AHP・Fuzzy・加重和・EWMの役割

**事実**：AHPは動作群・物体群の相対重みを同定する。旧 `scripts/AHP/get_comparison_mtx_v3.py:62` は最大固有値の固有ベクトルを正規化しCIも計算する。新 `risk_core/aggregators/legacy_ahp_adapter.py:12` も固有ベクトルを使うがCI/CRを返さない。集約時に加重和を使うことはAHPの代替ではなく、同定した重みの適用である。

**分析**：AHPによるカテゴリ内の重要度と、Fuzzyによるカテゴリ間の条件依存関係という役割分担は、[paper/draft/paper_simple_draft_v12.md:83](/home/hayashide/kazu_ws/master_thesis/paper/draft/paper_simple_draft_v12.md:83)、`:93` の研究目的と対応している。

**事実**：通常の上位Fuzzyは `μhigh(x)=x`、`μlow(x)=1-x`。2入力4隅の後件を `cHH,cHL,cLH,cLL` とすると、範囲内の有限入力では

```text
F(x,y) = cHH*x*y + cHL*x*(1-y)
       + cLH*(1-x)*y + cLL*(1-x)*(1-y)
```

となる。4ルールの適合度和は1。実装は `scripts/fuzzy/fuzzy_reasoning_v5.py:224,247,262` と `risk_core/aggregators/fuzzy.py:53`。middleの前件関数は定義されるが、この通常4ルールでは使われない。後件low/middle/highは0/0.5/1へ写像する。

**分析**：この方式は定数後件のFuzzy補間として説明できる。ただし「出力三角型集合の合成・面積重心」を一般に計算しているわけではない。旧修論PDFの本文pp.20–21（PDFページ30–31）の説明とは、等しい面積係数等を仮定した簡略化なのか仕様変更なのかの確認が必要。TFN CSVの左右幅 `l/r` は通常の上位推論では利用せず、中心 `c` だけ使う。

**事実**：内的静的の `fuzzy_multiply()` は左右の三角型数の斜辺交点と端点の平均を計算する。`l/c/r` の成分積でも、信頼度による積でもない。関数名だけから演算の意味を判断できない。固定の現在の属性集合を超えて利用する場合、交差・重なり形状が変わっても同じ式を使えるか別途検証が必要。

**事実**：旧修論本文p.37（PDFページ47、式3.44）は内的統合をαの単純重み和とし、その理由も記載している。したがって「このノードだけFuzzyでない」ことを直ちに不具合とは扱わない。問題は現行αが0.1固定で、スタッフ別取得値との対応が確認できないこと。

**事実**：EWMは `M:375` `ewm_master()` と `scripts/entropy/entropy_weight_generator.py:11,29` に残る。通常の `evaluate()` 内の呼出しはコメントアウト（M:455,459,463）。旧修論のEWM記述には関連研究の紹介もあり、「EWMが現行提案手法で有効」という証拠にはならない。

## 5. 改善の優先順位と推奨する改修方針

### 5.1 最初に行うべき整理

この段階では既存値を変えず、入力と有効設定を出力へ紐づける改修を推奨する。manifestにはコード版、入力ハッシュ、モデル名、集約方式、α、距離尺度、CSV解決パス・ハッシュ、後件値、欠損方針、通知方針を含める。出力フォルダ名だけのプロファイル管理を補う。

### 5.2 次に行うべき検証

**P1：現場知識と空間文脈の意味を検証する。** 回答→ノード・ルール対応、AHP CI/CR、Fuzzyの4隅対応・単調性、スタッフ代理方向、物体の関連付けを確認する。回答の非単調性は勝手に平滑化しない。内的重み和を維持する判断も合理的だが、その場合未使用のアンケート項目を現行モデルが利用していると説明しない。

欠損は「不存在」「未観測」「無効値」「観測済み中立」を区別する。最初は品質フラグと評価不能件数の追加を行い、その後研究者と補完方針を決める。全NaN姿勢→全動作最大という算術上の境界挙動は、公開入口の仕様として早期に対処する価値がある。

### 5.3 モデル変更が必要な場合の進め方

AHPとFuzzyを全面的に統一する改修は推奨しない。カテゴリ内の重要度はAHP、異なる因子の条件関係はFuzzy、属性と行動の混合は明示したα、という現行の役割を基準にする。EWMを採用する場合は「変動から得る重み」と「スタッフの重要度」の違いを定義し、現行モデルとは別の比較候補にする。

新設計は旧再現モードと並存させ、同一の凍結入力に対して、ノード別差分、総合MAE、同点を考慮した順位・首位一致、空間条件による順位逆転、スタッフプロファイル差を比較する。観測欠損を含む条件も別に集計する。通知件数は通知方針を固定した比較と、方針自体の比較を分ける。

特にK02の比較条件を先に揃えないと、空間文脈の有効性に関する再評価を解釈できない。K23の時刻照合を直さないと、新旧差分の量も信頼できない。

### 5.4 改修規模の目安

| 規模 | 主な内容 | 出力への影響 |
|---|---|---|
| 小 | 有効設定・出所保存、profile不足診断、CI出力、同点方針、休眠処理整理 | 通常のスコアを保存しやすい。診断・実行可否・集計は変わり得る |
| 中 | 比較条件統一、欠損状態導入、ノード契約・グラフ一致、α／ルール対応、時刻照合、寄与説明 | 対象ケースの評価・順位・説明が変わる。既存図表の再評価要否を判断する |
| 大 | 視線・遮蔽・直接支援、患者と物体の関係、複数スタッフ統合、動作識別用の追加特徴量 | 観測モデル自体が拡張。データ取得と妥当性評価を伴う |

今回はこれらを実装していない。

## 6. コードだけでは判断できず、研究者への確認が必要な事項

1. **論文・各図表の正本はどの経路か。** v5、新risk_core、リアルタイムv4、weighted_max等の実験条件を特定したい。保存済みCSVの生成版はコード配置だけでは確定できない。
2. **α=.1はどう決めたか。** 共通固定値なのか、個別回答から同定した代表値なのか。No.1–4を使わない方針は全実験に適用するのか。草稿の「スタッフ別α」を維持するのか。
3. **1A-Qdの回答は何へ使うか。** 現行の固定スタッフFuzzyとの対応、使わない設問の扱いを確認したい。
4. **RQ1の空間文脈なし条件は何か。** 同じFuzzy階層で空間入力0にするのか、最終値を内的リスクへ置き換えるのか。既存の論文図がどちらの条件か。
5. **Fuzzyの定式化は定数後件補間か、出力三角型集合の面積法か。** TFN幅は使う予定があるか。旧修論Table 3.9のlow距離・high方向→middleからhighへの改訂理由も確認したい。
6. **非単調回答は意図か転記か。** アンケートの条件順とTFN行順を照合し、単調性を制約にするか、回答者差として保持するか決めたい。
7. **高CIのプロファイルは採用対象か。** 尺度変換・入力転記・再回答履歴、CI/CRの採用条件、回答者数とCSV数の関係を確認したい。
8. **見守りの操作的定義は何か。** 接近方向を代理指標として使う範囲、停止中の監視、複数スタッフ、直接支援、遮蔽をどこまで研究対象にするか。
9. **物体の存在と患者への関係をどう扱うか。** 最近傍車椅子＝使用中とみなせるか。壁＝手すりとみなせる施設条件か。手すりなしの0は意図か。
10. **欠損と不存在の評価方針は何か。** スタッフ未検出を不在扱いするのか、ステーションで見守りがあると仮定するのか。属性・姿勢・位置の欠損で評価を継続すべきか。
11. **動作ノードの意味は何か。** 立ち上がりは遷移動作か立位状態か。ブレーキ解除と車椅子移動を別スコアにする識別根拠はあるか。手首・足首の名称と取得式はどちらが仕様か。
12. **距離尺度・高さ閾値・4乗の根拠は何か。** 実測校正、ヒアリング、予備実験、便宜的設定のいずれかを確認したい。
13. **候補表の椅子・杖・直接支援とEWMは採用予定か。** 未実装の候補を現行特徴量と混同せず、将来仕様に分けたい。
14. **説明は高い要因の列挙か、総合リスクへの寄与の説明か。** 現行表示で求める説明可能性を確認したい。
15. **スタッフ別スコアは相互に比較するか。** 現行ルールはプロファイルごとに基準値・尺度が変わる。患者内・同一プロファイル内の順位比較と、スタッフ間の絶対値・通知件数比較をどこまで評価目的にするか。

以上は調査から生じた確認事項であり、設計意図や研究結論を独断で確定するものではない。
