# 既知情報から確定できない危険要因・関係を同定する数理設計

## 1. 何を入力し、何を明らかにするか

スタッフが患者の立ち上がりを知っていても、近くのIVポールまでは知らない場合を考える。システムが持つ観測情報で危険を評価すると同時に、スタッフが知っている事実だけに合う別の状況も評価する。その別の状況では、IVポールが離れている可能性がある。これらを比較し、**現在の観測では成立するが、既知情報だけでは成立すると確定できない危険内容**を探す。

比べるのは、同じ判断設定で評価した状況の違いである。人による判断設定の差、事故発生確率、人の実際の理解を推定する計算は加えない。総合危険度だけでなく、危険要因・中間評価・実装済みの条件依存関係を対象にする。

本書は、既知情報と整合する有限個の状況を照合する設計案である。候補名K-HRWの採用や、新規性が確定したことを意味しない。設計の承認と実装の承認は別であり、本作業では実装・実験を行わない。

流れは次の六段階とする。

1. 同じ時刻の姿勢・患者位置・物体位置・スタッフ位置などを、一つの状況として保存する。
2. 全情報条件と既知情報条件の両方へ、同じ判断設定θを使う。
3. 既知事実に合う状況を候補一覧から残す。未知をゼロへ置き換えない。
4. 現在の観測と残した各状況について、危険要因・中間評価・総合危険度を計算する。
5. 現在成立している評価内容について、既知事実からも成立が確定するかを調べる。
6. 確定しない内容と、それを確かめる代替状況を出す。人の既知の関係・危険内容は別のタグとして併記する。

## 2. 入力と、既知情報の意味

| 記号・入力 | 内容 | 初期PoCでの扱い |
| --- | --- | --- |
| x* | システムの現在の観測。患者集合と物体・スタッフを同時に保持する | シナリオの一状態として指定。「全情報」はシステムの観測範囲であり、現実の完全な真実ではない |
| θ | AHP重み、Fuzzy回答値、モデル構成、下位変換設定 | すべての状態・比較法で固定。実回答とAI補完の来歴を保持 |
| L | 比較対象とする有限の同時状態一覧 | 各状態にraw姿勢・座標・属性など、既存評価を実行できる情報を保持 |
| K_F | 把握している観測事実 | 値・許容誤差・判定対象を含む制約として指定 |
| K_E | 把握している要因間の関係 | 関係IDごとの明示タグ。関係の規則を知ることと、現在その条件が成立すると知ることを区別 |
| K_R | 把握している危険内容 | 患者・時刻・評価内容IDごとの明示タグ。総合危険度を知ることから、個々の根拠を知るとは推定しない |
| E | 比較する評価内容の定義一覧 | 危険要因の区分やFuzzy条件の成立を、各状態で同じように判定する |
| I | 重要性の条件 | 対象とする内容・閾値等を設計設定として指定。臨床的な正解とは分ける |

K_E・K_Rのタグは `known`（既知と指定）、`not_known`（未把握と明示指定）、`not_assessed`（未評価）の三つとする。記載なしは `not_assessed` であり、未把握へ自動変換しない。これらは実験条件であって、本方式が人から推定した認識ではない。

事実の知識収集票には `known / not_known / not_assessed` と原回答を保存し、`known`の項目だけを計算用K_Fの制約へ変換する。残り二値はΩを狭める制約にはしない。事実がnot_knownでも、その事実に関わる危険内容まで未把握と確定するわけではない。この区別は評価設計007・ソフトウェア設計008と共通であり、上記のK_Fの定義を変更しない。

K_Fの例は「患者Pの姿勢が指定した姿勢と一致する」「IVポールの位置は未指定」である。派生した危険要因値を既知事実にする場合も、その値がどのraw状態から得られたかを残し、状態全体への制約として判定する。視野内で観測可能だったことだけではK_Fへ入れない。

### 2.1 同時状態を使う理由

同じ姿勢から複数の動作リスクが計算され、同じスタッフ位置が距離と方向の計算へ使われる。したがって「ある動作リスクだけ変更し、同じ姿勢に由来する残りは任意に固定する」という補完では、実際に作れない状態が混ざり得る。

Lでは一つの状況内のraw変数を一緒に保持する。複数患者を扱う場合も、スタッフや物体を患者ごとに独立に動かした状態を混在させない。既存のFeatureFrameへ患者別に変換する前に、同時状態の整合性を点検する。

物体が存在しない状態と、その位置を知らない状態も分ける。既存コードの `None` は物体不在等として評価されるため、未知値の代用にはしない。

### 2.2 既知情報と整合する状態集合

K_Fの制約をc_1,…,c_mとし、

\[
\Omega(K_F)=\{x\in L\mid c_j(x)=\mathrm{true}\quad\forall j\}
\]

と定義する。初期設計では分布を仮定せず、残った各状態が可能であると扱う。

必要条件は、Lが非空で、x*を含み、Ωも非空で、x*がΩに入ることである。既知の事実が現在の観測と矛盾するときは `inconsistent`、現在の観測がLにないときは `out_of_support` として判定を停止する。矛盾や空集合を「全部確定した」「未認識リスクが多い」と解釈しない。入力の必須値の欠落や入力のNaN等は `invalid_input`、モデル出力の欠落や非有限値は `model_error` として分ける。数値境界を判定できない場合は `boundary_unresolved` とし、runを結果不完全として扱う。

Lの全状態を調べても、Lに含めなかった連続座標・姿勢まで保証したことにはならない。出力には `scope=finite_library`、状態一覧の版、残った状態IDを必ず付ける。

## 3. 何を一件の評価内容として数えるか

本書でいう「事象e」は、各状態について成立・不成立を判定できる評価内容である。例えば「患者PのIVポール近接リスクがτ以上」を一件とする。閾値や区分を場面の結果を見て付け替えず、Eの版として固定する。

### 3.1 危険要因・中間評価・総合危険度

既存のスカラー値v_n(x;θ)について、

\[
h_e(x;\theta)=\mathbf 1\{v_n(x;\theta)\geq\tau_e\}
\]

を基本形とする。対象は危険要因12種と、内的リスク・外的リスク・総合危険度を含む中間・総合の7種を基本にする。初期PoCはシナリオに必要なものだけをEへ登録する。

患者属性・年齢属性は、現在の実装では三つ組の値で保持される。独自の平均値等へ勝手に数値化して閾値対象へ加えない。属性の違いはraw状態又は既知事実として扱い、スカラーの内的静的リスクへ反映された値を評価できる。

登録項目は `event_id, patient_id, event_type, source_node_id, predicate, importance_condition, definition_version`。event_typeは `factor`、`intermediate`、`total`を分ける。閾値τはモデル内の評価区分案であり、医学的に検証された危険閾値を意味しない。

総合内容を知っているタグがあっても、IV近接等の根拠は別IDである。総合危険の再提示を除外しつつ、根拠不足の候補を残せる。

### 3.2 実装済みFuzzyの関係

実装が持つ二入力Fuzzyは、入力u,vと、HH/HL/LH/LLに対応する回答値a,b,c,dについて、

\[
F_\theta(u,v)=auv+bu(1-v)+c(1-u)v+d(1-u)(1-v)
\]

\[
=d+(b-d)u+(c-d)v+\delta uv,\qquad
\delta=a-b-c+d
\]

である。high=u、low=1−u、積型の四条件をすべて持ち、回答値を代表値として使う現実装で成立する。既存のモデル構成と入力順を読み取って使い、別のFuzzy方式へ一般化しない。

関係の登録は、次の二つを分ける。

| 種類 | 何を表すか | 初期設計での使い方 |
| --- | --- | --- |
| 状態依存のFuzzy条件 | 現在、二入力が所定の区分に入り、その出力が所定の区分になること | `fuzzy_condition`事象としてΩ上の成立を照合 |
| δの構造注記 | 固定θの局所式が固定加算だけでは表せないか、その符号と値 | `nonadditivity`注記。δ自体を未知の状態事象として数えない |

例えば `u≥τ_u AND v≥τ_v AND Fθ(u,v)≥τ_out` を一つのFuzzy条件事象とする。τ群はEの設定案であり、現実の因果関係を表さない。δ=0なら条件の同時成立は登録できるが、非加算的な特別増幅とは表示しない。

δはθ固定なら全状態で一定なので、δ≠0だけを事象にしても、既知情報による成立の曖昧さは生まれない。δuvは原点を基準にした式の積項であり、患者の事故リスク増分やShapley相互作用値ではない。特にδ<0を正の増幅と呼ばない。

既定ルールでは総合・外的のδは0、内的・見守りのδは−0.5である。個別回答の場合は実際の値から計算し、仮定した正の相互作用を加えない。条件の発火度と、出力における積項の符号・値も分けて保持する。

見守り段階の四条件は、コード上の並びがHH/HL/LH/LLと異なるため、配列の位置だけでa,b,c,dを割り当てない。各条件の入力名とhigh/lowを照合し、同じ入力順のHH/HL/LH/LLへ対応付ける。

登録可能な関係は、内的静的×内的動的、スタッフ距離×見ていない方向の代理値、外的静的×見守り状況、内的×外的の四段階に限定する。立上りとIVポールの専用の特別増幅が、この一覧に存在するとは扱わない。

### 3.3 関係を知ることと、現在の成立を知ること

K_Eで「内的リスクと外的リスクをこの規則でまとめる」と知っていても、現在の外的リスクを知らなければ、現時点のFuzzy条件の成立は確定できない。そのため、K_E=knownだけで、状態依存事象を候補から除外しない。

K_Rで「患者Pについて、現在の事象eを既に把握」と具体的に指定した場合は、同内容の再提示を除外できる。K_Eは関係の理解タグ、K_Rは今回の具体内容の既知タグとして、意味を保つ。

## 4. 同定問題と出力

各eについて、現在の成立h_e*=h_e(x*;θ)、有限集合での下端l_e、上端u_eを計算する。

\[
l_e=\min_{x\in\Omega(K_F)}h_e(x;\theta),\qquad
u_e=\max_{x\in\Omega(K_F)}h_e(x;\theta)
\]

- l_e=u_e=1：既知事実から成立が確定する。
- l_e=u_e=0：既知事実から不成立が確定する。
- l_e=0,u_e=1：既知事実だけでは成立を確定できない。

x*∈Ωなので、h_e*=1ならu_e=1である。この不変条件が破れたら、評価又は状態対応の不具合として停止する。

計算上の候補集合を、

\[
U_F=\{e\in E\mid h_e^*=1,\ I_e(x^*,\theta)=1,\ l_e=0\}
\]

とする。I_eは登録した重要性条件であり、初期PoCではモデル内の対象条件にすぎない。候補ごとに、成立している現在状態と、不成立になる代替状態を一つ以上返す。これは有限集合における識別不能の根拠であって、人が実際に気付いていなかった証明ではない。

### 4.1 計算候補と、与えた認識タグを混ぜない

出力は次の二経路に分ける。

| 経路 | 条件 | 出力の意味 |
| --- | --- | --- |
| `factual_ambiguity` | e∈U_F | K_Fからeの成立を確定できないという計算結果 |
| `provided_knowledge_gap` | 現在成立する対象内容についてK_E又はK_Rが明示的にnot_known | 実験条件として与えた未把握タグ。算法が認識状態を発見した成功に数えない |

全事実が既知でΩ={x*}なら、U_Fは空になる。K_E=not_knownによる関係の提示は残せるが、それは入力タグに基づく提示である。K_E・K_Rがnot_assessedなら、人の理解は未評価のままにする。計算上確定したことから理解済とは推定せず、タグがないことから未理解とも推定しない。

K_R=knownのeは `already_reported_known` として再提示候補から除外するが、l_e,u_eやU_Fの計算記録は残す。総合内容だけ既知なら、factor等の根拠候補は別に残す。K_E=knownは関係理解の不足提示を除外するだけであり、事実不足による現在の条件成立候補を消さない。

### 4.2 構造化出力の項目

一件の出力は、少なくとも以下を含む。

- `event_id, patient_id, event_type, true_value, predicate, importance_condition`。
- `identified_from_facts`: `entailed_true / entailed_false / ambiguous`。
- `lower_truth, upper_truth, true_state_id, counterexample_state_ids`。
- `known_relation_tag, known_risk_tag, candidate_reason, presentation_status`。
- 関係事象なら `relation_id, input_node_ids, input_values, consequent_values, delta, delta_sign`。
- `model_version, theta_id, theta_hash, library_version, knowledge_version, event_definition_version, scope`。

スカラー出力の最小・最大も補助表示できるが、確率や人の未認識の強さに変換しない。候補の件数や成立状態の割合も、Lの作り方に依存する。初期設計では新しい合成スコアによる順位付けを行わず、重要性条件と種類を分けた一覧で返す。

## 5. 具体的な計算手順

以下は実装へ渡すための擬似コードであり、実行コードではない。

```text
入力: 現在状態 x*, 固定設定 θ, 同時状態一覧 L,
      既知事実 KF, 関係タグ KE, 危険内容タグ KR, 事象定義 E

1. x* が L に含まれること、raw状態の整合、θ、Eの版を検証する。
   必須入力の不足又は入力のNaN等なら invalid_input。
   x* が一覧外なら out_of_support。

2. Ω ← L のうち KF の全制約を満たす状態。
   Ω が空又は x* ∉ Ω なら inconsistent。以後の同定を停止。

3. Ω の各状態 x と各患者 p について、同一θで既存RiskEngineを評価。
   factor_risks、upper_risks、total_riskを保持。
   Fuzzy関係は登録された二入力と回答値から、同じ式で条件を評価。
   モデルの必要出力が欠ける、又は出力が非有限なら、0で補完せずmodel_errorで停止。
   事象の数値境界を確定できなければboundary_unresolvedとし、runを結果不完全にする。

4. E の各eについて現在成立、全状態での成立、重要性を評価。
   l_e、u_e、反証状態IDを記録。
   eが現在成立し重要でl_e=0なら factual_ambiguity として保持。

5. 同じeへのKR=knownなら再提示は除外。ただし計算記録は保持。
   KE/KR=not_knownに基づく内容はprovided_knowledge_gapへ分離。
   not_assessedは未評価表示のまま。タグを推定しない。

6. 種類別の候補と、除外・確定済みの監査用一覧、入力版を出力。
```

計算回数は、状態数N、患者数Pに対して既存評価N×P回と、事象照合N×|E|回である。小さな有限PoCを想定し、今回の設計では高速化を研究目的にしない。θとLを固定した評価表は再利用できるが、K_F・Eの条件を変えたことは別版として残す。

現在のRiskEngineは、入力がない場合に0を使う箇所がある。その既定値を未知表現に使わず、各状態で必要な値が揃ったことを呼出し前に検証する。既存コードの改修は本設計では実施しない。

## 6. 手計算で分かる例

以下は設計説明用の数学例であり、実データの結果ではない。

### 6.1 総合差が同じでも根拠が異なる

IVと車椅子への近接値が、現在状態では(0.8,0.2)、代替状態では(0.2,0.8)とする。現行の物体三種に合わせ、IV・車椅子・手すりの重みをそれぞれ1/3、手すり距離リスクを両状態とも0.2と置く。この重みは全比較値1の一対比較行列から得られる正の等重みであり、手計算のための仮定である。実スタッフの設定や採用済みのθとは扱わない。外的静的リスクは現在(0.8+0.2+0.2)/3=0.4、代替(0.2+0.8+0.2)/3=0.4となる。他の入力と同じθを固定すれば、外的リスクと総合危険度も両状態で同じになり、全情報の総合危険度と二状態の条件付き期待値の差も0になる。

「IV近接値≥0.6」という事象は現在成立し、代替状態では成立しない。したがってU_Fへ入る。一方「車椅子近接値≥0.6」は現在成立しないため、現在の未確定危険候補へは入らない。

この二状態は危険要因値を直接差し替えず、患者位置を固定して二物体の距離を入れ替えるraw状態として構成する。near_object_risk=1−距離/正規化長なので、0.8と0.2に対応する距離を持つ例は紙上で設計できる。実際の部屋配置・物体条件が成立するかはシナリオ設計で確認する。

これは総合値だけの差分に対する負例であり、IVを出力として使う多出力の条件付き解析に対する不能例ではない。

### 6.2 実装可能な条件依存を示す局所例

説明用に(a,b,c,d)=(1,0.25,0.25,0)とすればδ=0.5で、F(u,v)=0.25u+0.25v+0.5uvとなる。現在(0.8,0.8)ならF=0.72、代替(0.8,0.2)ならF=0.33である。uとvがともに0.6以上かつ出力0.6以上という条件事象は、現在成立し代替では不成立になる。

この係数は回答尺度で表せる設計用の例で、誰かの実回答だとは扱わない。局所の入力が同時raw状態から実際に得られるかは別途確認する。立上り×IV専用増幅を作った例ではない。

同じ条件判定でδ=0の設定を使っても、同時条件の成立自体はあり得る。その場合、出力に非加算の増幅があるとは表示しない。

## 7. 必ず含める負例と不変条件

| 条件 | 期待する挙動 |
| --- | --- |
| S01：立上り未知 | 該当事象が現在成立しΩに反証状態があれば候補。全状況で成立なら、事実未指定だけでは候補にしない |
| S02：IV位置未知 | IV事象の成立が変わる場合に根拠候補。立上りとの専用増幅は追加しない |
| S03：全事実既知・関係not_known | U_Fは空。与えた関係未把握タグによる別経路の表示だけを行う |
| S04：同総合・IV/車椅子入替 | 総合差0でもIV事象が未確定なら候補。多出力既存法にも同じ事象を与える |
| S05：全事実・全対象内容既知 | 新たな計算候補とタグ由来の未把握提示はともに空 |
| S06：未実装interaction | 立上り×IV専用増幅を出力しない。上位の条件依存を専用の因果関係と言い換えない |
| Ωが空／x*が除外 | inconsistentで停止。未認識として採点しない |
| Lにx*がない | out_of_supportで停止。似た状態へ勝手に置き換えない |
| 全状態でe成立 | eのKF識別はentailed_true。KE/KR未評価なら人の認識は未評価 |
| KR総合のみknown | 総合再提示は除外。個別factorの根拠不足は独立に保持 |

K_Fへ正しく制約を追加すると、Ωは狭くなる。現在状態を含む限り、同じE・重要性条件の下で、計算上の曖昧候補U_Fが増えることはない。これは設計の検証条件であり、人が情報を得るほど必ず見落としが減るという心理的な主張ではない。

状態を追加したLでは、従来確定したeが曖昧へ変わり得る。したがって、ライブラリの大きさを変えた結果を同じ保証として比較しない。

## 8. 既存法との比較と、新規性の判断

### 8.1 有限状態の含意判定とは同等

「すべての整合状態でeが成立するか」という制約含意判定を直接行えば、本方式と同じ答えになる。本方式はその結果にモデル内の事象ID、反証状態、既知タグを付ける設計であり、この計算原理自体を新規と主張しない。

独立の比較実装で同じ答えが得られることは、正しさの照合として重要であるが、既存法より優れた同定性能の証拠ではない。

### 8.2 条件付き期待値でも同じ候補を拾える

Ωの全状態へ正の重みw(x)>0、総和1を与え、共通の成立指示値h_eについてq_e=Σ_x w(x)h_e(x)を計算する。h_e*=1なら、

\[
q_e<1\quad\Longleftrightarrow\quad
\exists x\in\Omega(K_F):h_e(x)=0
\]

である。不成立状態が一つでもあればその正の重みだけq_eは1より小さく、なければq_e=1となる。

従って、全事象に条件付き期待値を計算し、現在成立かつq_e<1を選ぶ強い比較は、U_Fと同じ候補を拾える。SHAPを全計算しないと比較にならない、とはしない。

同じ条件付き背景と事象出力に対してSHAPの寄与和を使い、効率性が成立すれば、寄与和はh_e(x*)−q_eに対応する。個々の特徴量寄与の大小で選ぶ方法とは区別する。Conditional SHAPやShapley Interactionの非ゼロ値を、Fuzzyのδ又は実装済み相互作用の存在証明と同一視しない。

ゼロ重みの可能状態を除外する、背景分布を変える、近似計算の閾値を使う場合には同値性が崩れ得る。これは情報や定義の差であり、そのまま同定性能の優位としない。

### 8.3 比較で共通にする入力

θ、L、K_F、K_E、K_R、E、重要性条件、数値判定、出力への変換を共通にする。提案側だけに関係事象や既知タグを与えない。総合危険度だけを出す弱い比較に加え、各事象を出力にした条件付き期待値・多出力SHAP等の強い比較を置く。

既存法が寄与、提案が候補集合という異なる出力を返す場合は、その変換規則を比較前に固定する。既存法の本来の出力と、候補集合へ変換した出力を区別して残す。

### 8.4 正解と棄却条件

有限表上のモデル正解は、別の照合手順による全状態の事象成立表から作る。提案と同じ関数を呼び直しただけの確認は独立検算と呼ばない。手計算例や、別担当が数値・条件を確認した表を併用できる。臨床的に重要な危険の正解はこの表から作らず、別の根拠・評価へ分ける。

強い既存法と同じ候補を出すなら、方法論的な同定能力の優位は主張しない。PoCの価値は、現モデルと知識条件を対応させた統合仕様・検証可能性に限定して再評価する。違いが出た場合も、閾値・背景・状態・タグ・出力対象の差を先に点検する。臨床正解や人の実認識を本方式が当てたことにはしない。
