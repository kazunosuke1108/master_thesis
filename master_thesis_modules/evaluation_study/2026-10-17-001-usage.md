# 指定瞬間の順位アンケート試作ツール

REQ-003 revision 7 R-08 / AC-08に基づく試作です。場面、回答形式、同順位・判断不能の扱いは本調査の確定条件ではありません。算出式や主要評価指標は変更していません。

回答者へ渡すのは、生成先の `participant/` だけです。`analysis/` と `evaluate` の出力には、元の患者ID、知識源の名称、算出値が含まれます。出力一式を回答者へ渡さないでください。自由記述の場面説明についても、順位・算出値・本人知識の名称が含まれていないか、作成者が確認してください。

## 入力とコマンド

リポジトリのルートで実行します。出力先には存在しないディレクトリを指定してください。既存ディレクトリは上書きしません。パスに空白がある場合は引用符で囲んでください。

```bash
python -m master_thesis_modules.evaluation_study bundle studies/REQ-003/prototype.yaml /tmp/new-questionnaire-bundle
python -m master_thesis_modules.evaluation_study validate studies/REQ-003/prototype.yaml /tmp/responses.csv
python -m master_thesis_modules.evaluation_study evaluate studies/REQ-003/prototype.yaml /tmp/profiles.yaml /tmp/new-analysis --action-aggregation weighted_sum --responses /tmp/responses.csv
```

`--action-aggregation` は `weighted_sum` または `weighted_max` を明示します。`--responses` は任意で、指定すると本人回答と算出結果を結合した `comparison.csv` を保存します。いずれも統計指標は算出しません。

manifestは次の形式です。`scenario` はmanifestの置かれたディレクトリからの相対パスです。患者対応はシナリオ内の全患者と一致させ、匿名IDを重複させないでください。場面の既定値や選定候補はコードに埋め込んでいません。

```yaml
schema_version: 1
cases:
  - case_id: C01
    scenario: relative/path/to/scenario.yaml
    time_s: 0
    description: 指定時点の場面説明
    patient_ids: {A: P01, B: P02}
```

`ScenarioLoader` で読み、指定時刻以下の全イベントを `EventEngine` で適用し、同じ状態を `FeatureEncoder` へ渡します。時刻はシナリオの開始時刻から終了時刻までとし、ステップ幅へ丸めません。同じ時刻のイベントは入力順で適用します。シナリオ名によるlegacy入力への切替はありません。

位置はイベントで与えられた値です。スタッフ速度を積分して位置を進める処理は行いません。SVGのx軸は右、y軸は上で、単位はmです。スタッフの矢印は1秒分の速度ベクトルで、視線を表していません。重なった物体や患者は、図に添えた座標・動作の一覧でも確認できます。

姿勢特徴量が直接指定された患者は、動作ラベルが古いまま残る可能性があるため、`patient_descriptions: {A: 説明}` のように、元の患者IDをキーとする説明を追加してください。この説明と姿勢特徴量の対応は作成者が確認します。直接指定がない場合は、既存の動作プリセットを使います。スタッフの移動方向以外の見守り状態は推定しません。

## 回答CSV

列の名前と順序は次のとおりです。匿名回答者IDは英数字・ハイフン・アンダースコアで記入します。

```csv
case_id,respondent_id,patient_id,rank,status,reason
C01,S01,P01,1,ranked,
C01,S01,P02,1,ranked,
C01,S01,P03,3,ranked,
```

順位を回答するときは、全患者の `status` を `ranked` にしてください。`rank` は小さいほど優先です。同順位には同じ整数を記入し、その後は人数分を飛ばします。例えば `1,1,3` とし、`1,1,2` は受け付けません。この競争順位は試作の保存形式であり、本調査の分析規則を採用したものではありません。

場面全体を判断できないときは、全患者の `status` を `unable`、`rank` を空欄とし、各行の `reason` に理由を記入してください。一部患者だけの順位はこの試作では扱いません。空回答、患者の欠落・重複・追加、回答者IDの欠落、場面の欠落、順位の不正、`ranked` と `unable` の混在を検出します。回答者ごとにmanifest内の全場面・全患者が必要です。空の回答雛形は有効な回答と見なしません。

## 本人知識を使う解析

`profiles.yaml` は次の形式です。知識源名を含むため、回答者向けのディレクトリに置かないでください。`common_dir` はこのファイルからの相対パスです。

```yaml
profiles:
  - respondent_id: S01
    common_dir: knowledge
    ahp_profile: synthetic
    fuzzy_profile: synthetic
```

指定先には `comparison_mtx_30000001_synthetic.csv`、`comparison_mtx_30000010_synthetic.csv`、`TFN_synthetic.csv` の3件が必要です。AHPは既存の項目順の7×7、3×3行列、TFNは既存ローダーの12行以上・3列形式です。欠落時に旧絶対パスや既定の知識へ切り替えません。

既存の `make_profile_risk_config` と `RiskEngine` を使い、モデルは `spatial_context` とします。AHP行列は既存ローダーが上三角を使い、下三角と対角を再構成します。TFNの中心値の内部統合は先頭4行、外部統合は行番号5・4・7・6、最終統合は8〜11の順です。行番号は0始まりです。既存の外的動的統合など、個人CSVが供給しない設定は既存の設定を引き継ぎます。実際の全設定は `configs.json` に保存します。

`system-ranks.csv` は匿名回答者×場面×匿名患者×時刻ごとの算出値・順位を保存します。同じ浮動小数点値には同順位を付け、近似一致の許容幅は使いません。`--responses` がある場合は、回答者集合がprofilesと完全に一致することを確認し、本人の順位・判断不能・理由を結合します。順位の差から成功率などの指標を定義する処理は含みません。

## 再現記録と制約

manifest、シナリオ、使用コードのSHA256、Git HEAD・ブランチ・未コミット状態、生成日時、コマンド引数、作業ディレクトリ、Python・numpy・pandas・PyYAMLの版を保存します。解析では知識源ファイル・設定・回答CSVも追跡します。乱数を使わないためseedはnullです。未コミットのコードもハッシュで追跡しますが、コードそのものの完全な保存を代替するものではありません。

AI向けの設問には、同じ構造化場面情報と回答形式のみを含めます。期待順位、算出式、算出値、実スタッフの知識は渡しません。AIによる予行の結果は、設問の理解やデータ接続を確認するために使い、実スタッフの評価結果と区別してください。

場面ごとのHTMLは閲覧用です。`participant/questionnaire.html` は、知識回答36問と全場面の順位を通して答えるローカルフォームです。開始ボタンを押すと入力でき、初期回答は空欄です。匿名回答者IDと回答種別（`synthetic_ai` または `human_trial`）を選び、全設問を回答して完了します。未回答・不正値は完了を拒否します。AHPの24比較から逆数行列を作り、Fuzzyは内部・外部・総合の各HH・HL・LH・LLの順で12回答を保存します。

完了すると、全回答JSON・順位CSV・知識CSVを手動でダウンロードできます。全回答JSONの形式は `REQ003-full-session-trial-v1` で、既存のAI専用変換とは別形式です。順位CSVはこのツールの検証コマンドへ渡せます。開始・完了のUTC時刻と単調時計による経過ミリ秒を記録し、完了後は固定します。経過時間には説明を読む時間・休憩を含みます。ダウンロードに掛かる時間は含めません。知識CSVにも回答種別と同じ時間記録を付けます。構造化場面情報のSHA256を全回答JSONに保存します。このhashは知識の設問文やJavaScript全体を含まないため、フォームの版はbundleのprovenanceにあるソースhashと併せて確認してください。

通信・外部送信・自動アップロードはありません。実データCSV・映像との同期、動画・CCTV表現、Googleフォームへの配布、主要指標の算出は対象外です。知識回答も含めて5分以内に終わるかは未検証です。ブラウザの自動入力テストで得る時間を、実スタッフの回答時間として扱いません。

## 全回答JSONから本人解析への取込

フォームで保存した全回答JSONは、専用importerで既存形式へ変換できます。元JSON、回答種別、時間記録、知識の項目順、元ファイルhashを保持します。`human_trial` と `synthetic_ai` を区別し、種別とsyntheticフラグの不一致を拒否します。知識CSVの単独取込には対応していません。

```bash
python studies/REQ-003/import_questionnaire.py SOURCE.json MANIFEST.yaml NEW_IMPORT_DIR
python -m master_thesis_modules.evaluation_study evaluate MANIFEST.yaml NEW_IMPORT_DIR/profiles.yaml NEW_ANALYSIS_DIR --action-aggregation weighted_sum --responses NEW_IMPORT_DIR/responses.csv
```

全回答JSONの形式・項目順・全知識・時間・場面hash・全患者の回答を検証した後に、新規ディレクトリへ保存します。既存出力を上書きしません。Fuzzyの1〜5回答を `(answer-1)/4` で中心値に変換し、試作ではl=c=rとして保存します。これは判断の不確実性幅を推定した値ではありません。
