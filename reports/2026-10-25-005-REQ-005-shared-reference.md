# REQ-005 reference資料の共有参照

`reference/` 内のMarkdown・テキスト・PDFを、PMと専門担当、下書き生成へ共通で渡すようにした。既存の話題でも次の発言から反映する。起動中のbackendも更新し、資料一覧APIが `reference/2026-10-25-検討経緯.md` を自動参照対象として返すことを確認した。

現在の検討経緯の文書は11,513文字で、既存の読取上限内に収まる。Context.loadで全文の読取を確認し、truncatedはfalseだった。本文の書換えや、そこにある提案の承認は行っていない。

対象：[REQ-005 revision 3](../requests/2026-10-25-001-REQ-005-discussion-chatbot.md) R-07 / AC-07。研究責任者がreferenceの参照追加を直接指示したことを承認根拠とする。

## 追加した動作

| 対象 | 動作 |
| --- | --- |
| 資料一覧 | reference内のサブフォルダーを8階層まで調べ、.md/.txt/.pdfを一覧化。大文字の拡張子も扱う |
| 共通参照 | パス順で先頭8件を自動参照。それ以降の資料は画面から追加選択できる |
| 既存話題と担当 | 既存話題にも適用し、PM・選ばれた専門担当・下書き生成の入力に渡す |
| 更新 | 各生成前に読み直し、参照パス・SHA-256・読取範囲を既存の来歴に残す |
| 読取量 | 必須指示と対象REQ、明示選択資料、自動共有資料の順に渡す。既存の1件22,000文字・全資料100,000文字などの上限を維持する |
| 上限到達 | 一部だけの場合は抜粋、0文字の場合は未読と画面・保存文書へ表示する |
| 読取対象の限定 | 隠しファイル、非対応形式、symlinkを除外。以前選択した資料がsymlinkへ変わった場合も読込時に拒否する |
| Docker | referenceをbackendへ読取専用で渡す設定を追加 |

画面の参照資料には「全参加者が自動で参照」と表示する。既存の個別資料選択は維持し、共有資料をその選択枠へ勝手に追加しない。論文の研究方針・評価設計の採否は、引き続き要求書の承認記録に従う。
