# 研究相談グループチャット

ブラウザからPMや専門担当へ研究の相談ができます。対象REQ・原稿・報告を参照し、議論の要点をMarkdownの下書きにして、内容を確認してから保存します。frontendとbackendは別のDockerコンテナです。

実装対象は [REQ-005 revision 2](../../requests/2026-10-25-001-REQ-005-discussion-chatbot.md)。研究の計算コードとは依存関係を分けています。

## Dockerで起動する

Docker Compose、Dockerを操作できる権限、インターネット接続が必要です。このリポジトリを配置したLinux PCでの個人利用を想定しています。

リポジトリのルートから実行します。

```bash
cd tools/discussion-chatbot
./scripts/compose.sh build
./scripts/compose.sh run --rm backend codex -c 'cli_auth_credentials_store="file"' login --device-auth
./scripts/compose.sh up -d
```

ログイン時に表示された案内に従って、ご自身のブラウザで認証してください。完了後は <http://127.0.0.1:8080> を開きます。認証に使うコードやトークンを、会話やGitに貼り付ける必要はありません。

`compose.sh` はホストのUID/GIDをイメージの実行ユーザーへ反映します。通常の `docker compose build` を直接使う場合は `LOCAL_UID` と `LOCAL_GID` を設定してください。この作業環境のUIDは1003です。既定の1000のままビルドすると、ホストへのMarkdown保存が失敗する場合があります。UID/GIDを変更して再ビルドする場合、既存volumeの所有権も確認してください。

Codex CLIは0.163.0に固定しています。接続には、独自クライアント向けの [OpenAI Docs: Codex App Server](https://learn.chatgpt.com/docs/app-server) を使います。デバイス認証の利用条件は [OpenAI Docs: Authentication](https://learn.chatgpt.com/docs/auth) を参照してください。アカウント側でデバイス認証が許可されている必要があります。

認証の保存方式は `file` に指定し、アプリ専用CODEX_HOMEのauth.jsonへ保存します。ホストの `~/.codex/auth.json` や既存セッションはコピーしません。Dockerの `codex-state` volumeで、このアプリ専用の認証と会話状態を保持します。画面の接続状態は30秒ごとに更新されます。ログイン後は画面の更新ボタンでも再確認できます。Codexへ送られるのは、会話と選択した研究資料です。

モデルを指定したい場合は `.env.example` を `.env` へコピーして `CODEX_MODEL` に利用可能なモデルIDを記入します。空欄ではCodexの利用可能な既定モデルを選びます。`CHAT_PORT`、`AI_TIMEOUT_MS` も変更できます。通常は `AI_PROVIDER=codex` を使います。

```bash
./scripts/compose.sh logs --tail=50
./scripts/compose.sh down
```

`down` は会話と認証を消しません。`down -v` はvolumeを削除するので、履歴を残す場合は実行しないでください。

## Dockerを使わずに起動する

Node.js 24以上、npm、Codex CLI 0.163.0、Python 3、`pdftotext`が必要です。`pdftotext`はDebian/Ubuntuの `poppler-utils` に含まれます。Docker内には必要なコマンドを導入する設定があります。

```bash
cd tools/discussion-chatbot
./scripts/login-local.sh
./scripts/dev.sh
```

画面は <http://127.0.0.1:5173>、backendは `127.0.0.1:8787` で動きます。停止はターミナルでCtrl+Cを入力します。ローカルの会話・認証は `.local/` に保存し、Git対象から除外します。

AI認証なしで画面と保存処理だけを確認する場合は、明示的にmockモードにします。

```bash
AI_PROVIDER=mock ./scripts/dev.sh
```

このモードの応答は動作確認用です。研究上の回答や評価結果として利用しません。Codexの接続が失敗したときに、自動でmockへ切り替わる動作はありません。

## 使い方

1. 「新しい話題」で、話題名と関連するREQ-IDを指定します。例えば評価の相談は `REQ-004`、このアプリの相談は `REQ-005` です。
2. 通常はPMへ話しかけます。相手の選択欄か `@evaluator` などで専門担当を指名できます。
3. 「みんなで議論」を選ぶと、PMが話題に応じて最大2名を呼び、担当の意見の後に整理を返します。「みんな」「議論して」などの発言でも有効になります。
4. 「参照資料」では、この話題で読む報告・要求書を最大8件選べます。原稿v18のPDFは存在する場合に最初から選択します。必須の指示、対象REQ、同REQの最新チェックポイントは自動で読みます。`reference/`のMarkdown・テキスト・PDFもサブフォルダーを含めてパス順で先頭8件まで、全参加者へ自動で渡します。9件目以降は参照資料から追加選択できます。隠しファイルとシンボリックリンクは対象外です。既存の話題にも次の発言から反映し、資料の更新は各応答前に読み直します。
5. 返答中も次の発言を送れます。返答は順番に処理します。「停止」は現在の返答を、「待機を取消」は未着手の発言への返答を止めます。
6. 残したい話ができたら「会話から下書きをつくる」を選びます。編集・プレビューと校正候補を確認してから「内容を確認して保存」で書き出します。

`reports/` のメモとGit除外の引継ぎ記録へ保存できます。下書きの作成や保存は、研究方針・数式・評価条件の承認ではありません。初期版では既存要求書の合意欄を自動編集しません。採否は研究責任者が対象REQ・版を指定して判断し、通常の要求書運用へ引き継ぎます。

要求書・報告書の保存番号は、その日のrequests/とreports/を通じた次番号を使います。文書や参照資料が下書き作成後に変わっていたら保存を止めます。その場合は変更内容を確認し、下書きを作り直してください。保存済みの文書は、この画面から上書きしません。

## 指示・資料・履歴の扱い

会話はSQLiteへ保存します。AIの入力は、今回の問いまでのターンを順序どおりに並べた、直近30発言・合計60,000文字までです。各発言は先頭4,000文字までを参照します。資料にも読取量の上限があり、全文を読んでいない場合は画面に表示します。長い原稿の後半や細部について話すときは、関連する報告を選ぶか、該当箇所を会話に示してください。

各応答・下書きに、参照資料のパス、SHA-256、読取範囲、コード基準版を記録します。実際の入力資料が変わったらハッシュも変わります。過去の会話をすべて覚えているとは扱いません。以前のCodexセッションの会話状態は引き継ぎません。

AIの入力文脈をbackend側で管理するため、生成ごとに新しいCodexスレッドを使います。画面の役割と会話履歴はアプリが保持し、失敗した生成の途中内容や、順番待ちの未来の発言がAIの隠れた履歴に残ることを避けます。

コマンド実行・ファイル変更・外部ツールを無効化し、Codexから来る承認・ツール要求も拒否します。backendだけが、許可した資料の読取、PDF抽出、校正、確認済み文書の保存を担当します。共通指示・運用手順・yomiyasuの静的検査スクリプトは、Composeで必要なファイル・ディレクトリだけを読み取り専用で渡します。

会話ログや認証はDocker volumeまたは `.local/` に置き、Gitへ追加しません。研究資料は選択内容に応じてOpenAIへ送られるため、個人情報や認証情報を含む資料は選択しないでください。Markdown内の外部画像は自動取得しません。frontendはループバックにだけ公開し、backendはDocker内部だけで受けます。LANやインターネットへの公開は対象外です。

## 保存ロックの復旧

文書保存中にPCやプロセスが強制終了すると、`reports/.discussion-export.lock` が残る場合があります。保存が続けて409エラーになるときは、まずDocker・ローカル起動を含むすべてのbackendを停止し、他の保存処理がないことを確認してください。その後、このロックファイルだけを削除して起動し直します。稼働中のロックは削除しないでください。

保存中に強制終了した場合は、新規Markdownがすでにできていないかも確認してください。DBへの保存完了記録より先にファイルができる場合があります。研究メモを消さず、下書きIDと内容を確認してから必要な作業を判断してください。

## 検証

```bash
npm ci --prefix backend
npm test --prefix backend
npm run build --prefix backend
npm ci --prefix frontend
npm run build --prefix frontend
./scripts/compose.sh config --quiet
```

backendテストは一時ディレクトリと模擬AI・模擬Codexプロセスを使います。実際の認証や研究資料を使いません。README記載の起動と、認証済みモデルの応答までの確認は別の検証です。今回の実施結果と制約は [実装報告](../../reports/2026-10-25-003-REQ-005-discussion-chatbot-implementation.md) を参照してください。
