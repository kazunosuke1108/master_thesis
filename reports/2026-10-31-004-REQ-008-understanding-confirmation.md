# REQ-008：研究コンセプトとPoC方針の理解確認

## A. 研究コンセプトの理解要約

本研究は、スタッフの危険度順位を再現するのではなく、現在の患者文脈・空間的文脈から評価される重要な危険のうち、スタッフの既知情報だけでは把握・特定できない可能性がある危険と、その要因・関係を同定する研究です。全情報条件と既知情報条件には同じAHP重み・Fuzzyルール・モデル構成を使い、利用情報の違いに注目します。総合危険度の差だけでなく、要因別・中間段階・実装済みの関係を照合します。既知情報は条件として与え、未知をゼロとみなさず、通知は簡易出力とします。初期PoCはAI仮想スタッフをスタブとして少数場面で方式と評価を点検し、本評価では実際の医療スタッフへ置き換える方針です。中心は未認識リスクの同定・評価であり、認識推定、通知最適化、将来事故の予測へ広げません。K-HRWは未採用の候補で、新規性は既存手法との公平な比較で確かめます。

## B. Q1〜Q12への個別回答

### Q1：研究目的

順位一致は、スタッフと同じ判断を出せるかを問います。第三の目は、スタッフの既知情報では捉えられていない重要な危険を補えるかを問います。

例えば、スタッフが立ち上がりを把握していても、患者の近くのIVポールを知らない場合、その未把握の要因と危険評価上の意味を同定することが対象です。スタッフと同じ順位になることが成功条件ではありません。

### Q2：新手法を開発したい中心部分

中心は、三段階のうち「未認識リスクの同定・評価」です。

- 認識状態の把握：既知情報を実験条件として与え、自動推定を主対象にしません。
- 未認識リスクの同定・評価：全情報条件と既知情報条件を照合する、方法論的な検討の中心です。
- 通知：同定結果と根拠を確認できる簡易出力とし、UI・文面・対話の最適化を中心にしません。

### Q3：未認識リスクの定義

中心はAの、現在存在するとシステムが評価する危険について、スタッフが把握できていない可能性です。

Bの、見落としによる対応遅延が将来の事故リスクをどれだけ増やすかという予測は保留です。初期PoCは単一時刻を基本とし、過去の観測履歴を用いる拡張も今回の中心にしません。

### Q4：二つの危険度評価条件

同じ判断設定を使うのは、利用情報の違いによる影響を調べるためです。設定まで変えると、情報不足による違いと、重み・規則による違いを分離しにくくなります。

模範的判断設定との比較は、判断設定自体の適切さや、それが評価に及ぼす影響を扱う別課題です。初期PoCへ混ぜません。

### Q5：未知の特徴量

IVポール近接リスクをゼロにすると、「知らない」を「近接による危険要因がない」に置き換えてしまいます。その結果、人為的な情報補完による差を未認識リスクと誤認しかねません。

代替候補は、例えば次の二つです。

| 候補 | 必要な仮定・根拠 |
| --- | --- |
| 許容区間で扱う | 未知値の範囲を定め、その範囲が既知情報や他の入力と整合すること |
| 既知情報に条件付けた確率分布で扱う | 分布の根拠と、位置・姿勢などを共有する入力間の依存関係を定めること |

今回はどちらも選定せず、承認後の設計事項として残します。

### Q6：総合危険度差分の限界

存在し得ます。例えば、未知の位置関係について「車椅子近接リスクが高い状態」と「IVポール近接リスクが高い状態」が許容され、集約後の外的リスクや総合危険度が同程度になる場合です。総合値だけでは、実際にどちらの要因が成立しているかを区別できません。

危険要因別の評価、物体に関する集約結果、外的リスクなどの中間評価、実装済みの統合関係を比較する必要があります。

これは総合危険度の単純差分の限界を示す可能性の例です。Conditional SHAP等への反例とは断定できません。同じ情報・条件・評価対象で既存法が識別できる内容を確認する必要があります。

### Q7：事実の認識と危険の認識

既知特徴量の集合K_Fが同じでも、要因間の関係を把握しているか、危険内容まで認識しているかは分かりません。この違いを扱うには、K_EやK_Rに相当する追加条件が必要です。

ただし、どの区別を最低限実装するかは未決です。また、条件として与えた違いを扱えることと、人の認識を自動推定できることは別です。状態の項目を追加しただけでは、独立したアルゴリズム的新規性は成立しません。判断の違いだけを未理解と分類することもしません。

### Q8：現行Fuzzyモデルの限界

次の経路と設定を確認する必要があります。

- 立ち上がりが行動の集約を経て内的リスクへ入る経路。
- IVポール近接が物体の集約を経て外的リスクへ入る経路。
- 内的・外的リスクを総合危険度へ統合するFuzzy規則と、実際に使う回答値。

指定コードには、両者を直接組み合わせる専用規則はありません。ただし、上位の統合を経由した条件依存まで存在しないとは言えません。

特別な増幅がモデルに実装されていなければ、既存モデルの出力と内部構造を照合する同定器だけで、その増幅を抽出することはできません。モデル外の危険を新しく発見する課題とは分けます。

### Q9：AI仮想スタッフの位置づけ

AI仮想スタッフは、初期PoCで方式・研究課題・評価手順を点検するためのスタブです。既存資料や少数の模擬場面を使い、想定した同定ができるか、比較方法が成立するかを確かめます。

AIの回答だけを正解にはせず、模擬条件から定義できる正解や検証可能な性質と区別します。本評価・論文化では、実際の医療スタッフによる評価へ置き換える確定済みの方針です。

### Q10：評価設計

順位一致だけでは、スタッフが知らない重要な危険や根拠を新たに同定できたかが分かりません。

評価対象は、未認識の重要危険・要因・関係の同定、既知危険の不要検出、差分が小さい場面での検出、既知情報の変更への応答です。

総合危険度、単純差分、条件付き寄与分析、相互作用寄与分析、必要に応じたAXp等と比較します。その際は、与える情報をそろえ、出力対象の違いを調整して同じ問題として比較する必要があります。具体的な指標・正解・変換条件は、今回は決めません。

### Q11：方法論的新規性

候補名や既知情報の追加だけでは主張できません。同じ情報を与えた近い既存法に対して、何を追加で同定・評価できるか、その理由と適用条件を具体的に示す必要があります。

例えば、次の場合は案の再検討・棄却が必要です。

- 公平な比較で、既存法が同等の結果を出す。
- 改善が、提案側だけに与えた正解情報に由来する。
- モデルに存在しない相互作用を、存在するとして出力する。
- 正解を提案方式自身で作り、その復元だけを有効性とする。
- 未知値の恣意的な補完に結果が依存する。

実装の誤り、評価条件の不備、手法自体の不足は区別して判断します。

### Q12：総合理解と設計への接続

| 段階 | 理解 |
| --- | --- |
| 背景 | 限られたスタッフが複数患者を見守る |
| 課題 | 現在の重要な危険を把握できない、または認識が遅れる |
| 原因 | 情報把握が限定され、事実を知っていても関係や危険内容まで把握するとは限らない |
| アプローチ | システムの観測情報とスタッフ既知情報を照合する |
| 方式 | 同一判断設定で二条件の危険評価と階層内部を比較する |
| 技術的な研究対象 | 未認識の危険と、その要因・関係の同定・評価 |
| PoC | AI仮想スタッフをスタブに、少数場面で方式と評価を点検する |
| 本評価 | 実際の医療スタッフによる調査・実験へ置き換える |

逸脱しやすいのは、中心を通知文面の比較、対話、最小通知数、順位一致、将来事故予測へ移すこと、模範設定との比較を混ぜること、K-HRWを採用済みとして設計することです。いずれも今回進めません。

## C. 既存実装との整合性に関する確認事項

### コードを読んで確認できたこと

- [RiskEngineの返却部分](../master_thesis_modules/risk_core/engine/risk_engine.py)は、要因別・中間・総合の評価を返します。ただし、その返却型にルールごとの発火度は含まれません。参照：143〜162行。
- [個人別設定の入口](../master_thesis_modules/risk_core/engine/personalized_config.py)では、質問紙からAHP重みと四群のFuzzy回答を設定できます。既定設定が自動的に特定スタッフの回答になるわけではありません。参照：76〜114行。
- `action_only`や`patient_context`への切替は計算構成や総合出力を変えます。同一構成の全情報条件／既知情報条件とは同一視できません。
- [Fuzzy入力の欠損キーの0扱い](../master_thesis_modules/risk_core/aggregators/fuzzy.py)などは、既存計算の既定値です。スタッフが知らない情報の表現として、そのまま使えません。参照：76行。
- [見守り方向の計算](../master_thesis_modules/risk_core/factors/staff_risk.py)は移動方向を使い、実際の認識・記憶を測定していません。参照：35〜47行。
- 指定範囲では、K_F/K_E/K_Rを受けて二条件を照合する機構や、K-HRWの実装は確認できませんでした。現行説明文は大きな要因値を文章化するもので、未認識リスク同定とは異なります。

### まだ未確認のこと

PoCで使う具体的な判断設定・データ、未知値の扱い、必要最小限の知識区分、重要危険・関係の判定条件、比較手法との対応です。

### 研究責任者の判断が必要なこと

これらの具体化は承認後の設計段階で行い、手法の採用、主要評価条件、既存モデルの変更を確定する前に判断を求めます。今回は選定していません。
